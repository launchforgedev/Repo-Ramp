RepoRamp Documentation

Python Codebase Intelligence — scan, understand and improve Python repositories with structural analysis, dependency insights and actionable reports.

Install RepoRamp ↓ Run an analysis ↓ Ollama integration ↓ MCP integration ↓

What RepoRamp does

RepoRamp statically scans Python source files, parses module structure, maps internal imports, builds a dependency graph, detects dependency cycles, evaluates structural quality rules and writes Markdown and JSON reports. It parses source code; it does not execute the source files being analyzed.

Py
Python 3.10+

Supported Python runtime.

CLI
Terminal

PowerShell, Command Prompt, Linux shell or macOS Terminal.

i
Optional integrations

Ollama, MCP and Anthropic AI support are optional extras. Install only the integrations you intend to use.

1. Installation

Install from PyPI

Terminal 
python -m pip install reporamp

Install from the GitHub source

Terminal 
git clone https://github.com/launchforgedev/Repo-Ramp.git
cd Repo-Ramp
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"

For Linux or macOS, activate the environment with source .venv/bin/activate.

Install optional integrations

Terminal 
python -m pip install "reporamp[ollama]"
python -m pip install "reporamp[mcp]"
python -m pip install "reporamp[ai]"

For a source checkout, use python -m pip install -e ".[ollama]", python -m pip install -e ".[mcp]" or python -m pip install -e ".[ai]".

To install all three optional integrations alongside development tools in one source-checkout install:

Terminal 
python -m pip install -e ".[dev,ollama,mcp,ai]"

2. Requirements and verification

RepoRamp requires Python 3.10 or newer. Verify that the active environment can find the installed package.

Terminal 
python --version
python -m pip show reporamp
reporamp version
reporamp --help

If PowerShell reports that reporamp is not recognized, activate the environment in which RepoRamp was installed, or reinstall it using python -m pip install -e . from the repository root.

3. Analyze a repository

Open a terminal in the Python project you want to inspect and run:

Terminal 
cd path/to/your-project
reporamp analyze .

By default, RepoRamp writes both report formats to reporamp-report.

Generated files
reporamp-report/
├── report.md
└── report.json

Choose output directory and format

Terminal 
reporamp analyze . --output build/reporamp
reporamp analyze . --format md
reporamp analyze . --format json
reporamp analyze . --format both

Exclude paths and tune thresholds

Terminal 
reporamp analyze . --exclude tests --exclude "migrations/*" --max-deps 8 --max-fan-in 12 --max-module-lines 1200 --max-function-lines 120

Strict parsing and quality gates

Terminal 
reporamp analyze . --strict
reporamp analyze . --fail-on QR003,QR002
reporamp analyze . --fail-on cycles
i
Parse errors

Files that cannot be parsed are reported. Without --strict, parsing errors do not by themselves change the normal success exit code. With --strict, the command exits with code 1 when parse errors are present.

5. Project configuration

RepoRamp reads [tool.reporamp] from the pyproject.toml in the repository being analyzed. Command-line flags override configured defaults. An explicit --exclude list replaces the configured exclude list.

pyproject.toml 
[tool.reporamp]
max_deps = 8
max_fan_in = 10
max_module_lines = 1000
max_function_lines = 100
exclude = ["tests", "migrations/*"]
fail_on = ["QR003", "QR002"]
format = "both"
SettingTypeMeaning
max_depsInteger ≥ 0QR002 dependency threshold.
max_fan_inInteger ≥ 0QR004 importer threshold.
max_module_linesInteger ≥ 0QR006 module-size threshold.
max_function_linesInteger ≥ 0QR006 function-size threshold.
excludeList of stringsGlob patterns for paths to exclude.
fail_onString or list of stringsRule IDs to use as quality gates.
formatmd, json, bothDefault report format.

Unknown keys and invalid values are rejected rather than silently ignored.

6. Reports and JSON schema

Markdown report

report.md is the human-readable report. Depending on the analyzed project, it can include the summary, module inventory, dependency graph, dependency cycles, imports, quality findings, parse errors, coupling metrics and architecture summary.

JSON report

report.json is the machine-readable representation for scripts, tools and report comparison. It contains a top-level schema_version.

SchemaFields
1Summary, quality findings, modules, dependencies, standard-library imports, third-party imports, unresolved imports and dependency cycles.
2Adds parse errors, summary.parse_errors and coupling metrics: module, fan-in, fan-out and instability.

The report comparison command accepts schema versions 1 and 2. Report lists are sorted for deterministic output.

Coupling metrics

  • Fan-in (Ca): number of internal modules that import a module.
  • Fan-out (Ce): number of internal modules a module depends on.
  • Instability (I): Ce / (Ca + Ce); it is null when there are no internal edges.

7. Quality rules

Quality findings are structural signals for code review. They are not proof of a defect and should be interpreted in context.

RuleWhat it checks
QR001Empty Python modules. Empty __init__.py package markers are ignored.
QR002Modules with more outgoing internal dependencies than the configured threshold (default 5).
QR003Circular dependencies in the internal module graph.
QR004Modules imported by more internal modules than the configured threshold (default 10).
QR005Orphan modules not imported by another internal module. Recognized entry points and test-related modules are skipped.
QR006Modules or functions exceeding configured line-count thresholds (defaults 1000 and 100).

8. Compare reports

Generate a JSON report for each revision, then compare the baseline and updated reports.

Terminal 
# Run against the baseline revision
reporamp analyze . --format json --output base-report

# Run against the updated revision
reporamp analyze . --format json --output head-report

# Compare and fail if new cycles/findings are introduced
reporamp diff base-report/report.json head-report/report.json --fail-on-new

The diff reports added and removed modules and dependencies, plus new and resolved cycles and findings. With --fail-on-new, the command exits with code 2 when new cycles or findings are present.

9. Local Ollama codebase chat

RepoRamp can use an Ollama model running locally to answer questions about the generated analysis report.

Install Ollama and download a model

Install Ollama from ollama.com/download, then pull a model:

Terminal 
ollama --version
ollama pull llama3.2
ollama list

Install RepoRamp's Ollama extra

Terminal 
python -m pip install "reporamp[ollama]"

For a source checkout, use python -m pip install -e ".[ollama]".

Analyze and open chat in a separate terminal

Terminal 
reporamp analyze . --format both --ask

# Specify an installed model
reporamp analyze . --format both --ask --model llama3.2

On Windows, RepoRamp starts the chat in a new console window. On other platforms, chat runs in the current terminal. The analysis must generate report.json; Markdown-only output is not supported with --ask.

Chat from an existing report

Terminal 
reporamp chat --repository . --report ./reporamp-report/report.json
reporamp chat --repository . --report ./reporamp-report/report.json --model llama3.2

When no model is specified, RepoRamp discovers installed Ollama models. It selects the only model automatically, or asks you to choose when multiple models are installed. Type exit or quit to leave chat.

i
Context and limitations

The current chat passes the generated JSON report as context for each question. It is not a full source-code index, and it does not currently expose slash commands or persistent conversation history.

10. MCP server integration

RepoRamp exposes repository analysis functions as tools through the Model Context Protocol (MCP). The server uses stdio transport.

Install the MCP extra

Terminal 
python -m pip install "reporamp[mcp]"

For a source checkout: python -m pip install -e ".[mcp]".

Register with Claude Code

Terminal 
claude mcp add reporamp -- reporamp mcp
claude mcp list

Available MCP tools

ToolArgumentsReturns
analyze_repopathFull RepoRamp JSON analysis report.
get_cyclespathDependency cycles as lists of module names.
who_importspath, moduleInternal modules that import the requested dotted module name.
get_findingspath, optional rule_idQuality findings, optionally filtered by rule ID or cycles.

Each tool analyzes the repository path supplied in its arguments and respects that repository's [tool.reporamp] configuration.

i
Why does reporamp mcp appear to wait?

This command starts an MCP server over standard input/output. It is not an interactive shell. When launched directly without an MCP client, it may remain waiting for protocol input. Register it with an MCP client such as Claude Code.

Run the server manually

Terminal 
reporamp mcp

Manual launch is useful when an MCP client configuration starts the process and connects to its stdio stream. Do not send ordinary text commands into the server terminal.

11. Optional AI architecture summary

The optional Anthropic integration adds an AI-generated architecture summary to the report. It is independent of the Ollama chat feature.

Install the AI extra

Terminal 
python -m pip install "reporamp[ai]"

Set the API key

PowerShell 
$env:ANTHROPIC_API_KEY = "your-api-key"
Linux / macOS 
export ANTHROPIC_API_KEY="your-api-key"

Run analysis with AI summary

Terminal 
reporamp analyze . --ai

RepoRamp sends structured analysis context (module paths, internal dependency edges, unresolved-import count and dependency cycles) to the Anthropic API; it does not send the repository's source files through this feature. If the key, SDK or API request is unavailable, RepoRamp reports the reason and falls back to its built-in local architecture summary.

12. GitHub Actions

The repository includes a composite GitHub Action in action.yml. It installs RepoRamp from the checked-out action path and runs the analyzer.

.github/workflows/reporamp.yml 
name: RepoRamp
on: [pull_request]
jobs:
  reporamp:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: launchforgedev/Repo-Ramp@main
        with:
          fail-on: QR003,QR002
          args: --max-deps 8
InputDefaultPurpose
path.Repository directory to analyze.
fail-onQR003Rule IDs that fail the job; empty disables gating.
outputreporamp-reportReport output directory.
argsEmptyAdditional analyze arguments.
python-version3.12Python runtime used by the action.

Pin the action to a release tag or commit SHA for reproducible workflows once your release policy is established.

13. pre-commit hook

The repository includes a pre-commit hook definition in .pre-commit-hooks.yaml. Add RepoRamp to your project's pre-commit configuration:

.pre-commit-config.yaml 
repos:
  - repo: https://github.com/launchforgedev/Repo-Ramp
    rev: main
    hooks:
      - id: reporamp
        args: ["--fail-on", "QR003,QR002"]

The hook analyzes the repository when Python files change and writes reports to .reporamp-report/. Add that report directory to your .gitignore.

Install and run pre-commit

Terminal 
python -m pip install pre-commit
pre-commit install
pre-commit run --all-files

16. Troubleshooting

reporamp is not recognized

Activate the Python environment where RepoRamp is installed, then run python -m pip install -e . from the project root or reinstall the PyPI package.

Ollama support is not installed

Terminal 
python -m pip install "reporamp[ollama]"

No Ollama models are installed

Terminal 
ollama pull llama3.2
ollama list

Ollama connection fails

Check that the Ollama application/service is running and that ollama list can reach it. Confirm that the selected model appears in the list.

MCP dependency is missing

Terminal 
python -m pip install "reporamp[mcp]"

reporamp mcp waits without showing a prompt

This is expected for a stdio MCP server. It waits for an MCP client to start a protocol session. Register it with Claude Code or another compatible MCP client instead of treating it like a shell prompt.

--ask rejects Markdown-only reports

Use --format json or --format both, because chat reads report.json.

17. Git workflow for contributors

Create a feature branch, validate your changes, commit only the intended files, and push the branch to GitHub.

PowerShell / Terminal 
git switch -c feat/your-feature

# Validate
python -m pytest -v
python -m ruff check .

# Review and stage only the intended files
git status
git add src/reporamp/your_file.py tests/your_test.py
git commit -m "feat: describe your change"

# Publish the new branch and set its upstream
git push -u origin feat/your-feature

For later commits on a branch that already tracks its remote, use git push. Use git status before staging so generated reports, local environments and unrelated changes are not accidentally committed.
